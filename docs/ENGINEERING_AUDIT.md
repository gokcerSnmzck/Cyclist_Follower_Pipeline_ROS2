# Engineering audit

Reviewed 2026-11-16 against `4195d12` (`development`), before application changes.
The initial working tree was clean. Work continues on `portfolio/engineering-review`;
no commits, pushes, history rewrites or artifact deletions are part of this review.

## Evidence and scope

The audit covers both source trees, every package manifest/build definition and
launch/startup file, active perception/selection/fusion/control implementations,
Hybrid ReID modules, the CAN driver, historical variants, tracked assets and logs.
Historical variants were inventoried and compared to entry points; they have not
each received runtime validation. Generated `build/`, `install/`, `log/` trees
were counted and sampled for provenance, not treated as authoritative source.
The five binary USD stages cannot be semantically validated without USD/Isaac Sim.
No research report was found in this project tree; the only PDFs are system diagrams.
Consequently no report-to-source comparison or authoritative mapping from a
reported experiment to a Git revision is possible yet.

`home-goekcer-Projects-Cyclist_Follower_Pipeline_ROS2`, generation
`2026-11-16T13:36:15Z`, 1,015 nodes / 3,158 edges. Targeted class/method queries
and traces were fully paginated; coverage was checked for the candidate paths
and source/startup/simulation scopes. The index excludes the Ackermann scripts
and partially parses CAN driver lines 10/137 and root startup line 33. Those
sources were read directly. Graph call edges are advisory: one trace incorrectly
attributed a `project_3d_to_2d` call to the current matcher; the source has no such
call. Source inspection, not graph absence, supports the findings below.

References below are baseline source lines (unchanged except explicitly listed
metadata/model-label corrections). `R` means `src/`; `C` means

## Approval boundary and concrete next changes

The corrections above are deliberately limited to A11/A19 and documentation/tests.
All application algorithms, ROS interfaces, startup scripts, model selection,
GStreamer topology, CAN encoding and control constants retain baseline behavior.

1. **Freshness and identity (A01/A07/A08/A13/A16/A17):** add acquisition timestamps,
   bounded matching skew/age, empty-frame messages, unique IDs and explicit
   re-selection. Risk: target switches, rejected detections and altered stop timing.
   Accept only after recorded multi-person/occlusion/failure replay and interface tests.
2. **Control/CAN (A02/A03/A04):** agree finite-input rejection, command expiry,
   stop repetition, gear/brake semantics and physical-unit conversion. Risk:
   unexpected braking/steering/speed. Require protocol evidence, independent stop
   mechanism, disconnected CAN bench validation, then supervised hardware tests.
3. **Runtime/reproduction (A05/A06/A10/A12/A14/A15):** restore original vendor pins,
   validate SDK configuration, then repair startup and resource/error paths.
   Risk: different model outputs, memory negotiation and newly enabled actuation.
4. **Publication (A09/A20):** recover license/asset permissions; propose explicit
   tracked-file removal or model distribution changes. Do not rewrite history.

Approval is required by the task's Phase C restriction for these changes. They
remain proposals, not deployed fixes. A passing offline suite is not evidence
that the robot is safe to operate.
